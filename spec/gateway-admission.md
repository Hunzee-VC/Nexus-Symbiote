# Reference gateway admission

The gateway policy signer approves one agent, deployment, tenant, workload and actor. The gateway verifies a key-based DSSE envelope against its pinned policy-authority public key on every decision. It checks the approved snapshot's signed validity window and the latest trust data it has received. Its local trust window defaults to 24 hours and cannot extend the signed expiry.

## Operating the reference adapter

1. The policy authority reviews a full approved companion with a bounded validity window, policy digest, deployment and workload identity. It reviews the server and publisher evidence and explicit resource grants. The signing operation issues a new authorization. It does not authenticate arbitrary input claims from a scanner.
2. Prepare a binding JSON object containing `agent`, `deployment`, `tenant`, `workload` and `actor`. Run `symbiote admission sign approved.json binding.json --key authority.pem > bundle.dsse.json`. Supply keys through operator-controlled paths. Protect private keys and the directory containing the state database from untrusted principals.
3. The gateway authenticates the actor, workload and peer over the actual connection, then derives the same stable identity references and the observed `server/v1` digest independently. A tool-specific adapter maps a tool to one operation class and resolves an exact resource from the arguments. The adapter must reject unrecognized arguments and operations. Use `symbiote.enforce.admission.dispatch_call` at the dispatch boundary. Provide the pinned policy and approval keys. Use a separate private key to sign decision receipts.
4. For offline decision testing, run `symbiote admission decide bundle.dsse.json intent.json descriptor.json --policy-key authority.pub --receipt-key gateway.pem --state decisions.sqlite`. The intent contains the binding, a unique request ID, server ID, authenticated peer digest, tool name, action, resource and SHA-256 digest of RFC 8785 canonical arguments. The offline command trusts the operator-supplied intent and performs no tool side effect.
5. For production approval, the authorized reviewer inspects the exact bundle and invocation. Run `symbiote admission approve bundle.dsse.json intent.json --key reviewer.pem --expires <ISO-time-with-zone>`. Supply this envelope and the separately configured reviewer public key to the gateway. Approval covers the exact argument digest, resource, actor, deployment, request ID, bundle payload and time window. Atomic request consumption prevents a second dispatch with that request ID.
6. Verify audit evidence with `symbiote admission verify-receipt receipt.dsse.json --key gateway.pub`. A valid receipt proves that the gateway signed a decision. It contains the authority binding, operation, input digest, decision timestamp, snapshot, policy and bundle digests, trust serial and approval signer IDs. Use a tool-completion event for evidence that an allowed operation actually ran. Keep receipts as audit records, separate from permission tokens.

## Enforcement and limits

Declared, effective and observed grants survive the GAB projection. The exact-resource adapter requires a matching declared grant and a bounded effective grant for the exact request. Its authenticated actor and workload must resolve in the same tenant. Each grant must identify the approved policy, target tool or server and a credential issued to that workload for that target. Calls on behalf of a user need a single unexpired OBO hop from actor to workload whose audience and scopes cover the tool. Workloads acting as themselves need a task-scoped credential. Observed activity supplies no authority. The strongest approval requirement among matching grants prevails. Missing scope, wildcard scope, unknown gates, unsupported conditions, longer delegation chains, spend and egress constraints fail closed. The gateway admits only a single capability class per tool, a matching authenticated server digest and a verified, explicitly allowlisted publisher. Run applicable downstream IAM and egress controls for the actual side effect.

The signed bundle carries embedded revocations and quarantines. The policy issuer must publish one complete trust generation with the same serial on all entries. The oldest decision determines maximum staleness, the latest decision cannot be in the future, and the earliest expiry bounds use of the generation. The local SQLite transaction enforces monotonic snapshot and trust serials across actors and workloads for each tenant, deployment and agent. It rejects divergent contents at the same serial. A new revocation blocks matching calls as soon as the gateway evaluates the updated bundle. The verifier cannot know about updates withheld from it before its local freshness limit. Distribute updates actively, set a deadline appropriate to the deployment, and protect the state database from rollback. Multiple processes may share one local SQLite database. Multi-host gateways need a common transactional state authority.

The reference dispatcher commits a signed decision and consumes an allowed request ID before invoking the handler. A crash after committing can leave an allowed operation unexecuted. Downstream services that support retry should implement their own idempotency and completion tracking. Invalid input, signature, clock or state errors must stop dispatch.

`allowlist check` compares served descriptors and can detect interface changes. The GAB and OPA export preserve grant constraints. A generic gateway export refuses grants it cannot represent. Matching descriptors cannot detect an authenticated backend changing its effects. Enforce resource and destination limits where the operation executes.
