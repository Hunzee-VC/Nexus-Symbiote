# Collectors — the self-writing layer

A collector implements `symbiote.collect.base.Collector`:
`name`, `version`, `surfaces: [Surface]`, `mode: declared | observed`, `detect(ctx) -> bool`,
`collect(ctx) -> CollectionResult{entities, edges, evidence, coverage: SurfaceCoverage fragments, redactions}`.
Collectors are registered through the `symbiote.collectors` entry-point group, so third parties can ship
plugins. `symbiote scan` runs every collector whose `detect()` fires, each under a time budget (default 20 s;
whole static scan target < 60 s), and records `symbiote:collector:<name>:status`.

Rules for every collector: every fact carries `assurance`, `evidence.source` and an exact `locator`
(path + JSON Pointer / TOML key path / `file:line`); **secret values are never read into entities** — env-var and
header *names* are kept, values are replaced and the redaction recorded; a surface that cannot be read yields a
coverage status (`permission-denied | unreachable | not-attempted | truncated`), never an empty result; nothing
is executed from the scanned repository (no imports, no `eval`; Python configs are parsed with `ast`).

Zero-config `symbiote scan .` runs `mcp-config, instructions, skills, frameworks, models-hosted, models-local, sbom-merge, identity-config` (all offline) and reports the remaining surfaces as `not-attempted` together with the flag that enables each.

Fixtures: every supported config format has a fixture; a fixture MCP server (stdio, built with the `mcp` SDK) supports `--drift description|schema|annotations|order|pagination|unicode` modes so each drift produces the expected delta event; OTLP, k8s-aibom, cdxgen and registry samples; a Hugging Face snapshot fixture with safetensors + a pickle file + a chat template.

## Trust inputs for observed collectors

Configure these `CollectContext.options` in operator-owned settings outside the project or evidence being inspected.

| Collector | Required binding | Behavior on mismatch |
|---|---|---|
| `mcp-live` | Set `live=True`, list the server in `live_allow`, and set `live_executable_pins[server_id]` to the approved `sha256:<hex>`. Supply an absolute path to a self-contained stdio launcher. | Only a private copy of the pinned executable can start. Project arguments, environment and working directories are rejected. Run the worker in external isolation with restricted network and filesystem access. The pin covers the launcher bytes. |
| `otel-traces` | Set `otel_files` and `otel_scope` containing `agentbom.tenant.id`, `agentbom.deployment.id`, and `agentbom.snapshot.digest` for the selected agent. Select files from a trusted telemetry pipeline. | Unbound and mismatched spans yield coverage gaps. Files and source instances yield separate observations. Multiple response revisions for one alias leave its resolved version unknown. |
| `mcp-registry` | Supply exact package coordinates or the remote endpoint and an independent `package_digest` to corroborate a registry package hash. | Ambiguous, paginated and conflicting matches cannot yield a pinned artifact. Publisher authentication requires separate evidence. |
| Kubernetes importer | Retain producer signature metadata as a declaration. | CycloneDX properties alone cannot promote a model to verified. Verify the underlying signature and artifact independently. |
