# Symbiote — Design Brief (shared constraints for all architecture proposals)

Date: 2026-11-01. Target repo: /home/user/symbiote (branch claude/symbiote-foundation; currently only a one-line README + MIT license). Owner: aisecnomad.

## 1. Product thesis
Symbiote is the **Agent Bill of Materials (AgentBOM) toolkit** for the agentic-AI supply chain. It generates, validates, diffs, verifies, attests and enforces AgentBOMs for AI agents, and it **supports and extends CycloneDX 1.7 and SPDX 3.0.1 without forking either standard**.
It must answer, for any deployed agent: *Which agent is running, what can it access or change, where did its dependencies come from, who authorized it, and has any of that changed since approval?*
Four planes (from the source document): **Composition** (what was built or declared), **Authorization** (what the agent is permitted to do), **Observability** (what is deployed and what it has actually done), **Assurance** (why each claim should be trusted).
The companion Medium article ("The Supply Chain of Agency", Dahunsi) argues: no business-critical agent in production without a **signed** AIBOM covering models, datasets, RAG corpora, memory and SKILL.md files, A2A & MCP servers and tool schemas; cites the **Clinejection** incident (prompt injection via a GitHub issue -> AI issue-triager agent -> compromise of Cline's production releases) as the first prompt-injection-to-supply-chain cascade; maps to OWASP Top 10 for Agentic Applications (Dec 2025) ASI04 (agentic supply chain) and ASI06 (memory/context poisoning); names Google's **k8s-aibom** as a reference implementation and the OWASP AIBOM project guide as the step-by-step path.

## 2. Hard requirements
- **R1 CycloneDX 1.7 output validates against the official bom-1.7 JSON schema** (XML desirable). Use ONLY supported extension points: `properties` (name/value) with a documented, versioned property taxonomy under one namespace (proposal must choose and justify the namespace, e.g. `symbiote:` vs `agentbom:`; k8s-aibom uses `aibom.*`, cdxgen uses `cdx:` reserved + its own), `externalReferences`, `declarations` (claims/evidence/attestations/affirmation/assessors/targets), `compositions` (aggregate completeness), `formulation` (workflows for runtime assembly), `annotations`, `citations`, `dependencies` (dependsOn/provides), `services` (endpoints, authenticated, x-trust-boundary, trustZone, data flows), `metadata.lifecycles`, `signature` (JSF). Never invent top-level fields. Semantics that do not fit go into a **companion AgentBOM document with its own JSON Schema**, linked bidirectionally (externalReference + serialNumber/bom-ref + digest).
- **R2 SPDX 3.0.1 JSON-LD output validates** (spdx-python-model `v3_0_1` bindings: SHACLObjectSet / JSONLDSerializer; and the official JSON schema if located). Reuse `ai_AIPackage`, `dataset_DatasetPackage`, `software_Package`, Core `Agent/Person/Organization/SoftwareAgent/Tool`, `Relationship` with 3.0.1 `RelationshipType` values (verify which exist: usesTool, invokedBy, delegatedTo, trainedOn, testedOn, dependsOn, contains, ancestorOf, variantOf, hasEvidence?, ...), `LifecycleScopedRelationship` with `runtime` scope, and the **Extension profile** for custom AgentBOM elements in a Symbiote namespace. Note 3.0.1 ships `extension_CdxPropertiesExtension` (`cdxPropName`/`cdxPropValue`) — a built-in bridge for CycloneDX properties; use it for lossless round-trip. Provide forward-mapping notes for SPDX 3.1 (AIAgent/Prompt/RAG classes, `isoAutomationLevel`) but only as verified by Phase 1.
- **R3 One shared semantic model** (Pydantic v2) is the source of truth; CycloneDX and SPDX are *exporters/importers*. Importers: CycloneDX 1.5–1.7 (incl. k8s-aibom CDX 1.6 ML-BOMs and cdxgen AI-BOMs), SPDX 3.0.1. Every conversion emits a **loss report** listing each field that could not be represented.
- **R4 Content addressing as identity.** Canonical digests = RFC 8785 (JCS) + SHA-256 for: tool definitions (name, title, description, inputSchema, outputSchema, annotations, _meta?), instructions (exact bytes: system prompts, AGENTS.md, CLAUDE.md, SKILL.md, rules files, MCP manifests), prompt templates (+ variable schema), policy bundles. Models: per-file digest manifest compatible with OpenSSF model-signing manifests + Merkle root; serialization format with code-execution-on-load risk class (safetensors/onnx/gguf vs pickle/torch/trust_remote_code/Jinja chat template); typed derivation edges (fineTuneOf, adapterOf, quantizationOf, mergeOf, distillationOf, conversionOf) with parameters. Hosted models: provider + requested alias + resolved snapshot/revision + provider evidence, or an explicit `unknown` with a behavioral-fingerprint claim and expiry. **Name resolution is recorded**: requested ref -> resolved immutable ref -> verified signer -> transparency-log inclusion.
- **R5 Authority model.** Authorization/capability records attached to agents, tools and services: subject, capability class (read / write / execute / network-egress / filesystem / credentials / payment / communicate), scope pattern (resources, egress destinations, data classes, spend ceilings), granter + delegation chain (A2A), conditions, human-approval gate, validity/expiry, policy reference (digest), enforcement point, credential binding (static long-lived vs ephemeral/task-scoped; OBO token vs service account vs unauthenticated), identity references (SPIFFE ID, OAuth client id, service-account id — by reference, never secret values). Keep **declared**, **policy-derived effective**, and **observed** permissions distinguishable. Computed flags: Rule-of-Two / lethal-trifecta (untrusted input + private data + external communication), unpinned tool, floating model alias, destructive+open-world tool without approval gate, unsigned model, unsafe serialization.
- **R6 Runtime binding.** Snapshot = content digest + validity window + monotone serial + prior-snapshot link; signed append-only deltas (tool registered, description changed, model routed, sub-agent spawned, memory writer added); observed snapshots from live MCP `tools/list` and OpenTelemetry GenAI traces; `diff` across declared / approved / deployed / observed states where the diff IS the finding; allowlist export for gateways ("only components matching this BOM + signature are loadable"); action traces cite the active snapshot digest.
- **R7 Assurance.** Per-claim assurance level: declared / observed / verified (never a single score for the whole agent). Coverage statement per BOM: surfaces covered (code, registry, identity, model gateway, tools, data, runtime, network), sources queried, permission failures, truncation, exclusions; **unknown is distinct from verified absence**. Evidence/evaluation records: configuration tested (model, prompt, tools, data, policy digests), threat model, harness + version + dataset digest, attack conditions, results with denominators, assessor, validity conditions; mapped to OWASP ASI / LLM Top 10 2025 / MITRE ATLAS. AI-VEX-style statements scoped to (model, config) tuples with justifications like "not affected: tool disabled / guardrail enforced / approval required". Trust status: allowlisted / quarantined / revoked, keyed on identity.
- **R8 Attestation.** in-toto Statement v1 predicates (define predicateType URIs for: agentbom snapshot, tool-definition set, coverage, evaluation, registry resolution, observed delta) in DSSE envelopes; sign via sigstore-python (keyless OIDC, or key-based) with optional Rekor inclusion; verify; CycloneDX JSF signature optional. Evidence is referenced by digest from BOM claims.
- **R9 Self-writing generation (collectors).** MCP client configs (`.mcp.json`, `claude_desktop_config.json`, Cursor `~/.cursor/mcp.json`, VS Code `.vscode/mcp.json`, Windsurf, Codex `config.toml`, Gemini CLI `settings.json`), live MCP servers (`tools/list` via `mcp` SDK over stdio/streamable-http to compute **served** definition digests), skills (`SKILL.md` frontmatter + directory digest), instruction files, A2A Agent Cards (`/.well-known/agent-card.json` / `agent.json`), MCP Registry `server.json` entries (registry.modelcontextprotocol.io/v0/servers; `_meta["io.modelcontextprotocol.registry/official"]` has status/publishedAt/isLatest; no attestation fields), Hugging Face model refs (API when reachable; offline: local files hashed with model-signing), hosted-model configs (OpenAI/Anthropic/Bedrock/Vertex aliases), framework configs (LangGraph, CrewAI, OpenAI Agents SDK, Claude Agent SDK, AutoGen, Semantic Kernel), existing SBOMs (cdxgen/syft CycloneDX) merged as the software layer, k8s-aibom `AIBOM` CR / CDX 1.6 import as an *observed* source, OTel GenAI spans (JSON/OTLP file) as observed tool calls.
- **R10 Policy & conformance.** Built-in checks + exported OPA/Rego examples where the BOM is the input document; named conformance levels (e.g. AgentBOM-Minimal / Standard / Verified) with a validator; completeness/quality score with per-field reasons; CI exit codes.
- **R11 Transparency vs attack map.** Merkle-committed BOM (hash tree over components/claims) so a **redacted view can be verified against the signed root**; redaction is recorded, never silent (k8s-aibom precedent: `aibom.redaction.applied`).
- **R12 Developer experience.** `symbiote` CLI (Typer + rich; JSON output everywhere; stable exit codes), Python API, GitHub Action + pre-commit hook, mkdocs-material docs, worked examples (a realistic agent with MCP servers, skills, prompts, HF model, hosted model, RAG index, memory store, sub-agent), tests (pytest, hypothesis, golden files, validation against the official schemas), CI (GitHub Actions: ruff, mypy/pyright, pytest, schema validation), release (PyPI trusted publishing, SLSA provenance, Sigstore-signed artifacts), SECURITY.md, threat model, ADRs.

## 5. Non-goals for v0.1
GUI/hosted service; TEE/hardware attestation (reference only); embedding OPA (shell out or export Rego); live Hugging Face/network access in tests; implementing a gateway (export allowlists/policies instead).

## 6. What a proposal must contain
1. Semantic model: entity types, fields (name, type, required?, description), relationship/edge types with qualifiers, enums, identity & digest rules, snapshot/delta, authorization record, evidence/evaluation, coverage, trust status, assurance levels. Prefer a compact table per entity.
2. CycloneDX 1.7 mapping table (entity/field -> CDX construct; property taxonomy with exact property names; companion-document linkage) and what cannot be represented natively.
3. SPDX 3.0.1 mapping table (entity -> class/extension/relationship; namespace/IRI scheme) and 3.1 forward notes.
4. Conversion loss model and round-trip strategy.
5. Collectors: list, inputs, outputs, confidence/evidence locator per field.
6. Digest/canonicalization algorithms (exact field sets and encodings), model identity manifest, name-resolution record.
7. Policy/conformance: built-in checks (ids, severity, inputs, logic), conformance levels, scoring.
8. Attestation: predicate types and payload schemas, signing/verification flows.
9. CLI specification (commands, flags, exit codes, JSON outputs) and Python API shape.
10. Repository layout, module boundaries, testing strategy, CI/release, docs structure.
11. **Work breakdown**: 10–16 work packages that independent implementation agents can build in parallel with minimal file overlap (each: scope, files, interfaces it depends on, tests, acceptance criteria), plus an integration order.
12. Risks and open questions.

## 7. Addendum — k8s-aibom conventions to interoperate with (from its docs/schema-divergences.md, fetched 2026-11-01)
- Per-attribute confidence via properties: `aibom.confidence` ∈ {declared, inferred, unresolved, verified}; `aibom.evidence.locator` (exact source path, e.g. `spec.template.spec.containers[0].args[1]`), `aibom.evidence.source`; workload identity `aibom.workload.*`; controller provenance `aibom.controller.*`.
- Model signature facts: `signature.status` ∈ {unsigned, claimed, verified}, `signature.outcome` (incl. `signature-valid-unconstrained`), `signature.reason`, `signature.identity`, `signature.rekorEntry`, `signature.subjectNameMismatch`. "Valid signature, unconstrained signer" must never be laundered into "verified".
- `aibom.redaction.applied` names the redaction class whenever output sanitization removed material.
- It keeps a public **schema-divergence register** (D-NNN entries with status active/rescinded/upstreamed, spec section, rationale, upstream tracking: CycloneDX/specification#990 (2.0 RFC) and CycloneDX property-taxonomy#175 proposing official `ai:runtime:*` names). Symbiote must keep an equivalent register for every property/extension it emits, and its property taxonomy should be designed to be upstreamable.
- Symbiote's per-claim assurance levels (declared / observed / verified) must map cleanly onto k8s-aibom's per-attribute confidence (declared / inferred / unresolved / verified) when importing; proposals should define that mapping.
