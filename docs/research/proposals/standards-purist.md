# Symbiote — Architecture Proposal (Standards-First / Purist variant)

Author stance: CycloneDX/SPDX standards engineer. Date: 2026-11-01. Target: `/home/user/symbiote` (branch `claude/symbiote-foundation`). Companion to `DESIGN-BRIEF.md`; this proposal is independent of the other variants.

**Design thesis.** Symbiote emits documents that any stock CycloneDX 1.7 or SPDX 3.0.1 consumer can validate and partially understand, and that a Symbiote-aware consumer can understand completely. We achieve this with an *encoding ladder* applied to every fact, in strict order of preference: (1) a native field with matching semantics; (2) a native structure whose semantics are *narrowed* by a property qualifier; (3) a property under one registered namespace with a versioned, closed vocabulary; (4) a section of the companion AgentBOM document, linked bidirectionally by digest. Nothing is ever emitted at level 3 or 4 without an entry in the public divergence register, and nothing is ever invented at the top level of either format. Interoperability and lossless CycloneDX ⇄ SPDX round-trip are the first-class acceptance criteria; the round-trip harness is a work package of its own and gates every exporter.

Phase 1 outputs (`scratchpad/phase1/`) did not exist when this was written; every claim marked **VERIFIED** below was checked directly against the pre-downloaded schemas or the probe virtualenv during this design session; claims marked **ASSUMPTION** were not and must be confirmed by Phase 1 or an ADR.

## 1. Semantic model (source of truth)

Package `symbiote.model` (Pydantic v2, `extra="forbid"`, frozen value objects, `model_config = ConfigDict(ser_json_bytes="base64")`). Every entity is an `Entity` with a stable `id` (a `bom-ref`-safe string, never starting with `urn:cdx:`), and every *fact-bearing* field may carry an `Assurance` qualifier. The model is deliberately a thin superset of what CycloneDX 1.7 and SPDX 3.0.1 can jointly express; invention is confined to the authority, snapshot, coverage, evaluation and trust records that neither format has.

Hosted models: `requested_ref` = alias, `resolved_ref` = provider snapshot id or `Unknown(provider-undisclosed)` with `behavioral_fingerprint` claim attached to the `Model`.

### 1.9 Trust status, snapshot, delta

`TrustStatus{subject: id or identity digest, status: allowlisted|quarantined|revoked|unknown, authority: Party, since, until?, reason, evidence}`; keyed on identity (digest/purl/SPIFFE), never on display name.

`Delta{id, snapshot_before: Digest, snapshot_after: Digest, kind: tool-registered|tool-removed|tool-description-changed|tool-schema-changed|model-routed|sub-agent-spawned|memory-writer-added|instruction-changed|authorization-changed|registry-status-changed, subject: id, from_digest?, to_digest?, observed_at, source: SourceRun, signature: EvidenceRef?}`. Deltas are append-only; a `Delta` whose `snapshot_before` is not the current head is rejected (`E_DELTA_FORK`).

### 1.10 Identity and digest rules

1. Primary key of every component = **content digest** (`definition_digest`, `content_digest`, `manifest.root`, `bundle_digest`); `purl`/name are locators. `id` is `<kind>:<short-digest>` by default (`tool:3f9a…`), overridable.
2. Two entities with equal primary digests are the same entity across documents even if names differ (`symbiote diff` reports a rename, not a change).
3. Hosted models with `resolution_status=unknown` are keyed by `provider + alias + fingerprint digest`; the key expires with the fingerprint.
4. All digests are hex lowercase, algorithm-prefixed in string contexts.

### 1.11 Assurance level definitions (per claim)

- **declared** — asserted by the owner/supplier or read from configuration the owner controls (collector evidence: manifest/config path).
- **observed** — corroborated by a collector against the deployed system within a stated scope and time (live `tools/list`, OTel spans, k8s API, registry API, provider API).
- **verified** — evidence is authenticated (signature over the exact digest) and evaluated against an explicit trust policy with a constrained signer; `signature-valid-unconstrained` never qualifies.

k8s-aibom import mapping: `declared→declared`; `inferred→observed` with `technique=other`, `source=<k8s evidence source>`, and `confidence_hint=0.5` retained in `foreign_properties`; `unresolved→Unknown(not-collected)`; `verified→verified` iff `k8s-aibom:security:signing:outcome` is not `signature-valid-unconstrained` and `…:identity` is present, else `observed` (+ claim `signature-valid-unconstrained`). Reverse (export to a k8s-aibom-reading consumer): `declared→declared`, `observed→inferred` when `technique=other` else `declared`... **no** — observed facts are exported as `k8s-aibom:confidence=inferred` only when heuristic; otherwise Symbiote adds its own `agentbom:assurance` and leaves `k8s-aibom:*` untouched.

## 2. CycloneDX 1.7 mapping

### 2.1 Namespace decision: `agentbom`

Decision: **one top-level namespace `agentbom`**, registered in the CycloneDX Property Taxonomy registry (process: issue on `CycloneDX/cyclonedx-property-taxonomy`; the registry is CC0 and accepts project namespaces — k8s-aibom is registering `k8s-aibom` the same way). Rationale against `symbiote:`: a vendor-named namespace is a dead end for upstreaming and invites a third vendor vocabulary; `agentbom` names the *profile*, so when CycloneDX adopts agent semantics (2.0 Blueprints/behavior capability, issue #1015, taxonomy PR #175) the migration is a documented rename table exactly like k8s-aibom's `aibom.*`→`k8s-aibom:*` transition, and intermediate adopters can emit `agentbom:*` without reference to Symbiote. Rationale against `cdx:`: reserved — "unofficial sub-namespaces and names MUST NOT be used under cdx" (cdxgen's `cdx:agent:*` family violates this, which is itself an argument for a registered namespace). Emitter provenance needs no namespace: it is native `metadata.tools.components[]` plus `citations.attributedTo`.

Grammar (taxonomy ABNF): lower-case kebab segments, `:`-delimited, names may be camel-free; no spaces. Versioning: the taxonomy document is versioned (`agentbom-taxonomy 1.0.0`), the document advertises `agentbom:schema = 1.0.0` in `metadata.properties`; names are **add-only** within a major; a rename is a new name plus a register entry with status `rescinded` on the old one. Value encodings are closed: booleans `true|false`; enums lower-kebab; digests `sha256:<64hex>`; timestamps RFC 3339 UTC with `Z`; **lists are repeated properties** (CycloneDX explicitly allows duplicate names) never comma-joined; a JSON value is only ever stored under a name ending in `:json` and is JCS-canonical. A `*:unknown-reason` sibling carries the `Unknown.reason` when a value is unknown.

Top level: `agentbomVersion`, `subject{bomLink: "urn:cdx:<serial>/<version>", bomDigest, spdxDocument?: IRI, merkleRoot}`, `snapshot`, `coverage`, `authorizations[]`, `edges[]` (with qualifiers), `resolutions[]`, `evaluations[]`, `vex[]`, `trustStatus[]`, `deltas[]`, `merkle{algorithm, root, leaves[]{id, hash}, redactions[]}`, `lossReport?`, `collectors[]` (SourceRuns). Every `subject`/`target` is a `bom-ref` from the linked CycloneDX document; the schema includes a `$comment` per field naming the CycloneDX property it summarizes so the companion is self-describing for maintainers. The companion is **optional for AgentBOM-Minimal**, mandatory for Standard and Verified.
