# Collector reference

Every path each built-in collector reads, and what the `ide_agents` collector records from coding-agent settings. The [registry collector](registry-collector.md) and [model integrity](model-integrity.md) pages describe those two collectors in full, and the [known limitations](known-limitations.md) list what each collector leaves out. A test checks that the `prompt`, `rag`, `a2a` and `ide_agents` rows below name every path those collectors read.

## Coding-agent settings

For Claude Code, `ide_agents` records the permission mode (`bypassPermissions` is a high finding, `acceptEdits` medium), blanket grants in its allow list, how many allow, ask and deny rules and hook handlers it declares, and findings for hook commands, `apiKeyHelper`, MCP auto-approval, plugins and additional directories. It does not record the rules or hook commands themselves. For Codex it records the approval and sandbox settings, for Cursor its hook commands, and for Cursor, Windsurf, Cline and Codex an `agent.permissionMode` key in their JSON settings. The MCP servers that Codex and Gemini CLI settings declare are inventoried by the `mcp` collector.

Every settings file `ide_agents` recognizes is bound by a digest, so a changed value is a high `diff` alert. For Codex `config.toml`, `.cursor/cli.json` and the Antigravity, xAI and Copilot files, a change only to a value the redaction removes, such as a token, an MCP environment value or a URL path on the same host, alerts only with `NEXUS_SYMBIOTE_SOURCE_BINDING_KEY`, and the record then carries a low `completeness` finding, while a host glued to such a URL after a shell operator or another URL scheme still alerts. Without the key, a URL whose host URL parsers read differently, such as one with a backslash in its authority, is a collection failure. See [source binding](verification-source-binding.md#ide-agent-settings); [instructions and IDE settings](known-limitations.md#instructions-and-ide-settings) lists what this leaves out.
